# House Price Predictor — Data Mining, Machine Learning & Django

A two-part project:

* **Part 1 – Data-mining & ML pipeline** (`predictor/ml/`, plain Python + scikit-learn, no Django needed)
* **Part 2 – Django web app** (`predictor/`, `house_project/`) that wraps the pipeline in a browser UI

## Dataset

The app is built for Kaggle's **House Prices – Advanced Regression Techniques** (Ames, Iowa) data
(<https://www.kaggle.com/c/house-prices-advanced-regression-techniques/data> → `train.csv`, target `SalePrice`).
Kaggle requires a login, so the file is **not bundled**. Download `train.csv` and upload it in the app.

For a quick start, `sample_data/house_prices_sample.csv` (1,480 rows × 39 columns) follows the same schema and is
**synthetic** (generated by `tools/generate_sample_dataset.py`) with realistic missing values, outliers and duplicates.
Results on it are for demonstration; use the real Kaggle file for your final report/viva.

## Requirement checklist

| Requirement | Where |
|---|---|
| Dataset, 500+ rows, numeric + categorical | `sample_data/` or Kaggle `train.csv` |
| Missing values (median / mode imputation) | `pipeline.build_preprocessor`, table on *Data summary* page |
| Outliers (IQR + Z-score detection; capping; extreme price rows removed) | `pipeline.outlier_report`, `IQRCapper`, `clean_data` |
| Duplicates + irrelevant fields removed | `pipeline.clean_data` (IDs, constant, >50 % empty, free-text columns) |
| Scaling + encoding | `StandardScaler`, `OneHotEncoder` in `build_preprocessor` |
| Feature selection | `pipeline.select_features` (correlation), RF feature importance |
| EDA: distributions, box plots, scatter, heatmap | `predictor/ml/charts.py` → *Dashboard* page |
| Models + metrics | Ridge, Random Forest, Gradient Boosting; R², RMSE, MAE, MAPE (regression problem) |
| Upload `.csv` / `.xlsx` | *Upload* page |
| Summary: info, preview, missing values after processing | *Data summary* page |
| Dynamic dashboard | *Dashboard* page (+ column explorer drop-down) |
| Metrics + live prediction form | *Predict* page |

## Run it

```bash
python -m venv venv
venv\Scripts\activate            # Windows   (Linux/macOS: source venv/bin/activate)
pip install -r requirements.txt
python manage.py migrate         # optional: only silences the "unapplied migrations" notice
python manage.py runserver
```

Open <http://127.0.0.1:8000/> → *Use sample dataset* (or upload your own file).

### Pipeline only (no web server)

```bash
python run_pipeline.py sample_data/house_prices_sample.csv --out outputs
python run_pipeline.py path/to/train.csv --target SalePrice --out outputs
```

## How the pipeline works

1. **Cleaning:** drop rows without a price, identifier / constant / >50 % empty / free-text columns, duplicates, and
   extreme price outliers (beyond 3 × IQR).
2. **Split:** 80 % train / 20 % test (`random_state=42`). Everything below is fitted on the training part only.
3. **Feature selection:** numeric columns with |r| < 0.05 against price, or |r| > 0.85 with a stronger column, are removed.
4. **Preprocessing (inside the model, so no data leakage):** median / mode imputation → IQR capping → `StandardScaler`
   (numeric); mode imputation → One-Hot (categorical).
5. **Models:** Ridge, Random Forest, Gradient Boosting learn `log(1 + price)`. The best model is chosen by 3-fold
   cross-validation on the training data and then scored once on the test set.
6. **Prediction:** the form asks for the 8 most important columns; all other columns use their median / mode.

## Project layout

```
manage.py  requirements.txt  run_pipeline.py
house_project/        settings, urls
predictor/
  ml/pipeline.py      cleaning, outliers, selection, preprocessing, models
  ml/charts.py        all matplotlib charts
  ml/service.py       runs the whole pipeline for one upload and stores the results
  views.py forms.py urls.py runs.py templatetags/
  templates/predictor/  base, upload, summary, dashboard, predict
  static/predictor/style.css
sample_data/  tools/generate_sample_dataset.py
```

Each upload is stored in `media/runs/<id>/` (results, model, charts) and deleted after 24 hours.
The session only keeps the id of your current analysis (signed cookie), so no database table is needed.

## Notes

* `SECRET_KEY` and `DEBUG = True` in `settings.py` are for development only.
* Real Kaggle data uses `NA` to mean "feature not present" (e.g. no garage). The pipeline imputes the most
  frequent value; replacing it with a `"None"` category is a possible improvement.
